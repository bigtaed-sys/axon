# Участие в разработке

Проект открыт под MIT. Правки, замечания и разборы ошибок приветствуются.

## Собрать и запустить

Нужен Node 22 или новее — ядро использует встроенный в него SQLite.

```bash
npm install
npm run build      # все пакеты, в порядке зависимостей
npm test           # 233 теста
```

Десктоп:

```bash
cd apps/desktop
npm run dev        # разработка, с горячей перезагрузкой окна
npm run build      # сборка
npm run dist       # установщик
```

Ядро отдельным процессом:

```bash
node packages/daemon/dist/cli.js start
node packages/daemon/dist/cli.js help
```

## Устройство репозитория

Монорепозиторий на рабочих пространствах npm, проектные ссылки TypeScript.

```
packages/protocol     контракт ядро ↔ клиент: схемы, команды, события
packages/core         рантайм: хранилище, провайдеры, инструменты, агент
packages/daemon       HTTP + WS, пейринг, CLI
packages/client-sdk   клиентская библиотека
packages/plugin-sdk   типы для авторов плагинов
apps/desktop          Electron
examples/hello-plugin пример плагина
```

Зависимости направлены строго внутрь: `protocol` не знает ни о ком, `core` знает
только `protocol`, клиенты знают `protocol` и `client-sdk`. Обратных стрелок нет
и заводить их не нужно.

## Что стоит знать до первой правки

**Ядро — отдельный процесс, и он живёт долго.** Собрали новую версию — старая
осталась в памяти. Симптом обманчивый: «правка не применилась», «настройки ни на
что не влияют». Перезапускайте ядро после каждой сборки, особенно когда меняли
промпт: там ошибку видно не в логах, а в поведении.

**Сборка перед тестами обязательна.** Тесты клиентских пакетов идут против
собранного `dist`, а не исходников. `npm test` без `npm run build` может проверить
вчерашний код и радостно позеленеть.

**Строгий TypeScript.** `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`,
`verbatimModuleSyntax`. Необязательное поле — это `field?: T` **и** `| undefined`
там, где тип пишется руками. Импорт только с расширением `.js`.

**Меняете протокол — поднимите ревизию.** `PROTOCOL_REVISION` в
`packages/protocol/src/primitives.ts`. По ней клиент понимает, что ядро старше, и
показывает полосу с кнопкой перезапуска. Забыть её — значит оставить человека
наедине с необъяснимым поведением.

## Стиль

**Комментарии на русском.** Продукт русскоязычный, и код тоже. Это осознанное
решение, а не недосмотр.

**Комментарий объясняет «почему», а не «что».** `// увеличиваем счётчик` не нужен
— это видно из строки. Нужен тот, который объясняет, почему сделано так, а не
очевидным способом: какая альтернатива рассматривалась и чем она хуже, какая
ошибка здесь уже случалась, что сломается, если поменять. В коде таких много —
держитесь той же планки.

**Тест фиксирует поведение, а не покрытие.** Название теста — утверждение о
продукте («вытесняется самое выцветшее, а не самое старое»), а не имя метода.
Внутри — комментарий о том, почему это важно, если это неочевидно.

**Промпты — предписывающие.** Общее пожелание модель прочитает и не изменится;
запрет конкретного оборота — изменится. Это касается и текстов характера, и
описаний инструментов: описание отвечает не только «что делает», но и «когда
вызывать».

## Прислать правку

Отдельная ветка, осмысленные коммиты, `npm run build && npm test` перед
отправкой. Крупную переделку лучше сперва обсудить обсуждением или задачей —
чтобы не оказалось, что она расходится с тем, куда проект идёт.

Разбор ошибки полезнее правки, если непонятна причина: приложите, что делали, что
ожидали и что получилось. Для ядра пригодится вывод `axon status` и версия.
