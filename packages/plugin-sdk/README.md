# @axon-assistant/plugin-sdk

Типы для написания плагинов [Axon](https://github.com/bigtaed/axon).

Пакет нужен только редактору. В рантайме плагину импортировать из него нечего:
`api` приезжает аргументом в `activate`. Плагин без единой зависимости — папка,
которую можно склонировать и запустить, а не проект, который надо сначала собрать.

```bash
npm i -D @axon-assistant/plugin-sdk
```

## Из чего состоит плагин

```
my-plugin/
  axon.plugin.json   манифест — единственный обязательный файл
  index.js           точка входа, если у плагина есть код
  skills/*.md        инструкции текстом, если они есть
```

Плагин **без кода** — законная и частая вещь: манифест из десяти строк,
поднимающий чужой MCP-сервер.

## Манифест

```json
{
  "id": "weather",
  "name": "Погода",
  "description": "Прогноз для города пользователя",
  "version": "1.0.0",
  "api": 1,
  "main": "./index.js",
  "permissions": ["net"],
  "settings": [
    { "key": "apiKey", "label": "Ключ OpenWeather", "type": "secret", "required": true },
    { "key": "city", "label": "Город", "type": "text", "default": "Варшава" }
  ],
  "skills": "./skills",
  "mcpServers": {},
  "jobs": [{ "name": "утренняя-сводка", "everySeconds": 3600 }]
}
```

| Поле | Смысл |
| --- | --- |
| `id` | Слаг. Им префиксуются инструменты: `search` → `weather_search` |
| `api` | Версия API плагинов. Сейчас `1` |
| `main` | Точка входа. Нет — плагин без кода |
| `permissions` | `fs`, `net`, `shell`, `secrets`, `journal`. Показываются пользователю до установки |
| `settings` | Форма, которую нарисует интерфейс. `secret` хранится шифрованным |
| `skills` | Папка с `*.md` |
| `mcpServers` | Имя → транспорт. `${ключ}` подставляется из настроек при запуске |
| `jobs` | Задачи по расписанию. Обработчик вешается через `api.jobs.on` |

## Код

```js
export async function activate(api) {
  await api.tools.register({
    name: 'forecast',
    title: 'Прогноз погоды',
    description:
      'Узнать погоду в городе. Вызывай, когда спрашивают про погоду, ' +
      'дождь, температуру или что надеть.',
    tier: 'sensitive',
    parameters: {
      type: 'object',
      properties: { city: { type: 'string', description: 'Город' } },
      required: ['city'],
    },
    async execute({ city }) {
      const key = api.settings.get('apiKey');
      const res = await fetch(`https://api.openweathermap.org/…&q=${city}&appid=${key}`);
      return JSON.stringify(await res.json());
    },
  });
}

export function deactivate() {}
```

`execute` возвращает строку или `{ text, mime }`.

## Что даёт `api`

| | |
| --- | --- |
| `api.tools.register/unregister` | свои инструменты |
| `api.context.contribute(name, stability, fn)` | абзац в промпт |
| `api.skills.add` | скилл на лету (обычно они просто файлы в `skills/`) |
| `api.providers.register` | свой провайдер модели |
| `api.jobs.on(name, fn)` | обработчик задачи из манифеста |
| `api.journal.on(fn)` | события ядра (нужно право `journal`) |
| `api.settings.get/set/onChange` | настройки плагина |
| `api.memory.facts/remember` | долговременная память пользователя |
| `api.blobs.write` | большой вывод мимо контекста модели |
| `api.log.*` | в логи плагина, видные в интерфейсе |
| `api.dir` / `api.dataDir` | своя папка и папка для своих данных |

## Что плагин может попросить у ядра

До сих пор SDK был про то, как плагин **отдаёт** возможности. Обратная сторона —
четыре вещи, без которых серьёзный плагин не пишется.

**Спросить модель.** Ту, которую человек уже настроил:

```js
const кратко = await api.model.ask({
  system: 'Отвечай одним предложением.',
  prompt: 'О чём этот текст?

' + текст,
  maxTokens: 300,
});
```

Свой ключ заводить не нужно, и расход попадает в общий счётчик. Плагин с
собственным ключом означал бы, что человек платит дважды и второй раз не видит
за что.

Это один вопрос без истории и без инструментов. Нужен агент — им уже является
Axon; плагину незачем становиться вторым.

**Сказать человеку.**

```js
await api.notify('Сервер упал', 'не отвечает третью минуту');
```

Показывает тот клиент, который сейчас на связи, — у ядра экрана нет. Мера, а не
право: плагин, который звенит каждый час просто потому, что проснулся,
выключают в тот же день вместе со всей пользой.

**Сказать о себе.**

```js
await api.status.set('токен протух', true);   // покажется как «не работает»
await api.status.clear();                      // всё наладилось
```

Состояние плагина ядро выводит из состояния процесса: жив — значит работает.
Плагин, у которого отвалился внешний сервер, при этом живее всех живых и
молчит, а человек гадает, почему инструмент не отвечает.

**Поискать в переписке.**

```js
const найдено = await api.history.search('докер', 5);
```

Тот же поиск, что у агента. Плагин видел факты, но не разговоры — опереться на
контекст было неоткуда.

## Своя страница настроек

Рядом с плагином в списке есть шестерёнка — за ней страница, которую описывает
сам плагин. Описывает, а не рисует: ни разметки, ни кода для окна плагин не
присылает. Пусти его рисовать самому — и код плагина окажется в окне с полным
доступом к ядру, ровно там, откуда его убрали отдельным процессом.

**Разделы** группируют поля. Плоский список годится, пока полей пять; дальше
человек смотрит на два десятка подписей и не понимает, что с чем связано.

```json
"sections": [
  {
    "title": "Подключение",
    "description": "Токен берётся в настройках вашего аккаунта.",
    "fields": ["host", "token"]
  }
]
```

**Условные поля** появляются, только когда нужны:

```json
{ "key": "port", "label": "Порт", "type": "number",
  "visibleWhen": { "key": "mode", "equals": "self-hosted" } }
```

Без этого плагин с двумя способами подключения вываливает поля обоих сразу, и
человек заполняет половину впустую.

**Кнопки** — то, ради чего страница вообще нужна: настройки без способа
проверить, что они верные, это анкета, а не настройка.

```json
"actions": [
  { "name": "check", "label": "Проверить подключение", "section": "Подключение" },
  { "name": "reset", "label": "Сбросить кэш", "confirm": "Точно очистить?" }
]
```

```js
api.actions.on('check', async () => {
  const response = await fetch(`${api.settings.get('host')}/ping`);
  if (!response.ok) throw new Error(`Сервер ответил ${response.status}`);
  return 'Подключение работает';
});
```

Возвращённая строка показывается человеку зелёным, брошенная ошибка — красным.
Отказ здесь не поломка: «не удалось подключиться» — законный ответ кнопки
«проверить подключение», и падать из-за него нельзя, человек нажал именно
затем, чтобы это узнать.

Рабочий пример со всем сразу — [examples/feeds-plugin](../../examples/feeds-plugin):
разделы, условное поле, две кнопки, задача по расписанию, инструмент и вклад в
промпт, всё без единой зависимости.

## Как не сжечь бюджет пользователя

Это главное, ради чего Axon вообще существует, и плагин может всё испортить.

**Редкий инструмент помечайте `deferred: true`.** Тогда его схема не грузится в
контекст, пока модель сама не спросит. Пять инструментов с подробными схемами —
это несколько тысяч токенов в *каждом* запросе.

**Длинный вывод кладите в `api.blobs.write`,** а модели отдавайте краткую
сводку. Всё, что вернул инструмент, остаётся в истории разговора и
переотправляется каждый ход.

**`stability` у вклада в контекст выбирайте честно.** `stable` уходит в
кэшируемый префикс промпта, `volatile` — в хвост. Изменчивый текст (время,
курс, погода), положенный в `stable`, обнуляет кэш промпта на каждом ходу.
Ошибка не видна глазом и стоит десятикратной цены запроса.

**Длинные инструкции — это скилл, а не описание инструмента.** У скилла в
контексте постоянно висит одна строка; тело модель читает сама, когда задача
под него подходит.

## С чего начать

```bash
axon plugin new ./мой-плагин
```

Три файла: манифест, код и описание. Плагин из заготовки сразу работает —
поднимается, регистрирует инструмент и отвечает на кнопку, — так что первое, что
вы увидите, это работающая вещь, а не пустой шаблон.

## Настройки без ручного разбора

`get` возвращает `unknown`, и на нём легко ошибиться: пустое поле превращается в
`NaN`, а галочка из формы приходит строкой `"false"`, которая истинна. Для
частых случаев есть готовое:

```js
api.settings.text('greeting', 'Привет')   // строка, пустая — умолчание
api.settings.number('limit', 30)          // число, негодное — умолчание
api.settings.flag('notify', false)        // «false» из формы это ложь
api.settings.lines('urls')                // многострочное поле как список
```

## Как поставить свой плагин

**Из приложения:** Плагины → Установка плагина. Один экран, куда кладут что
угодно — ссылку на репозиторий, конфигурацию MCP или архив с плагином.
Приложение само разберёт, что ему дали.

Архив — обычный `.zip`: тот, что отдаёт «Download ZIP» на гитхабе, или
сделанный из папки проводником. Обёрточную папку внутри искать не надо, ядро
найдёт `axon.plugin.json` само. `.tar.gz` тоже принимается.

**Пока пишете плагин**, удобнее подключить папку по месту — тогда правки видны
сразу, без пересборки архива:

```bash
axon plugin link ./мой-плагин     # подключить папку как есть
axon plugin logs мой-плагин       # что он печатает
```

## Как это работает внутри

Каждый плагин запускается **отдельным процессом**. Бесконечный цикл, утечка
памяти или `process.exit()` внутри плагина убивают только его: ядро видит
падение, снимает регистрацию его инструментов и продолжает работать.

Обратная сторона — всё общение с ядром асинхронное и проходит через
сериализуемые сообщения. Возвращать из `execute` можно только то, что
переживёт `JSON.stringify`.

Песочницы при этом нет: процесс работает с правами пользователя. `permissions`
в манифесте — это информированное согласие, а не ограничение. Чужой
непроверенный код правильнее подключать как MCP-сервер.
